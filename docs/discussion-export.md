# Save a discussion for offline reading

After selecting a topic with `canvaspilot discussions 42`, save its cached thread:

```bash
canvaspilot export-discussion 42 71 --out discussion.html
canvaspilot export-discussion 42 71 --unread-only --out unread-discussion.html
```

Both IDs must be positive numeric Canvas IDs. The command accepts the same
`--base-url`, `--profile` and `--token` options as the existing reader. It uses the
configured client; it does not create a new authentication flow.

Open the resulting HTML file directly in a browser. It contains no scripts,
external styles, images, or other network resources. The topic and each returned
entry appear in reading order. Use the entry list and parent links to navigate a
long discussion, and the browser's Print command to make a paper copy or PDF.
The layout also fits a narrow screen. Entry text and scope stay visible in print;
collapsed original-field sections are optional inspection details.

## Read the thread accurately

The export consumes the existing `CanvasAPI.discussion_thread()` result exactly
once. That reader obtains one topic response and one cached view response with
GET requests. Exporting does not post, mark entries read, rate or subscribe.

The readable body is the reader's cleaned `message_text`, not rendered source
HTML. A deleted entry stays present with unavailable body and author. Missing
text and explicitly empty text have different labels. A media-only entry is not
given an invented transcription. Author names come only from the reader's
unambiguous participant association; missing or ambiguous associations remain
explicitly unavailable.

In unread focus, known unread entries retain their ancestors once, in source
order. Those ancestors are visibly marked as context; they are not extra unread
entries. Read, unread and unknown states remain distinct, as do forced-state
markers. An explicitly empty unread list may produce an empty selection. Missing
or ambiguous unread metadata can refuse unread focus, using the existing reader's
error behavior; it is not turned into a successful empty report.

Each entry exposes its structural `path` and `parent_path`. Parent navigation
uses those positions in the returned view, not original `parent_id` values.
The positions are not persistent entry identifiers. Original entry fields,
including a conflicting parent ID, remain available as escaped JSON inside
**Author association and original entry fields**. That section is source
inspection, not a second readable body or a fallback attribution. Source URLs
and markup remain inert text.

The report preserves reader warnings, unmatched unread identifiers, counts,
topic metadata and separate view metadata. A separate new-entry stream supplied
in metadata is not merged into the thread. Topic counts and observed tree counts
can differ. An empty selection does not prove there are no posts.

## Keep the original normalized data

**Download complete report JSON** saves `discussion-thread.json`. It contains the
complete normalized reader result, including original source fields and derived
reading aids, without adding or rewriting fields. It is not a copy of the raw
HTTP response pages. Numeric and string identifiers, false, null, zero, empty
strings, empty lists and source array order remain distinct.

Requested course/topic IDs and report creation time are separate export context.
The timestamp says when this HTML was produced, not when Canvas observed the
discussion. Canvas's view is cached and eventually consistent; this file does
not refresh or establish that the server cache included the latest posts.

Success prints a JSON receipt with `ok`, `output`, requested `course_id` and
`topic_id`, `selection`, `entries_included`, UTC `generated_at`,
`html_bytes`/`sha256`, and `json_bytes`/`json_sha256`. The HTML also displays the
download's SHA-256. These hashes identify the generated bytes; they do not attest
to the freshness of the Canvas cache.

## Choose a new destination

`--out` must name a new file in an existing directory. Existing files, directories,
symlinks and dangling symlinks are refused before any discussion request. The
command renders the whole report before publishing it through the existing page
packet writer. That writer stages and flushes complete bytes beside the output,
then exclusively hard-links them at the destination. A competing creator wins
without being overwritten. Filesystems that do not support this publication
operation fail without a replacement fallback.

A read, rendering or publication failure exits nonzero and writes a structured
error to stderr, without a success receipt or an incomplete final HTML file.
If publication succeeds but removal of the temporary source fails, the command
returns success with `cleanup_warning`; the warning names the remaining temporary
file. This follows the existing writer's contract and does not promise additional
crash durability.

Normalized JSON is limited to 4 MiB and rendered HTML to 16 MiB. Oversized and
nonfinite data refuse the whole export. No content is silently truncated to fit.
The saved document can contain participant names and original messages; choose
its destination and sharing audience accordingly.

## Python and development

```python
from pathlib import Path

from canvaspilot.discussion_export import build_discussion_report
from canvaspilot.page_export import write_page_packet

content, receipt = build_discussion_report(api, 42, 71, unread_only=True)
cleanup_warning = write_page_packet(Path("unread-discussion.html"), content)
```

The caller supplies an existing `CanvasAPI` instance. The pure helper
`render_discussion_report(report, course_id=42, topic_id=71)` accepts an existing
normalized report. Both helpers accept an optional timezone-aware
`generated_at` for deterministic local reporting. The existing CLI reader, API,
MCP tool, authentication and transport behavior remain unchanged.

Focused maintained checks:

```bash
pytest -q tests/test_discussion_export.py tests/test_discussion_export_cli.py
```

Qualification uses synthetic fixture data and local HTTP. It does not establish
access to any particular live course, account or discussion. See the
[discussion reader guide](DISCUSSIONS.md) for the normalized report contract.
